## What this means for your install

Everything in this release is about *getting the Android app built and downloaded*,
plus the app's launcher icon. There is no database change, no breaking change, and
nothing about how your photos are stored or served.

On a Docker install the headline is that building an APK no longer needs an image
rebuild: `compose.yaml` mounts the APK directory into the API, so a build is
downloadable the moment it finishes. The builder image also carried the wrong Android
platform, which made every build fail inside Gradle at the last step; that is fixed.

Rebuild your APK if you want the new launcher icon. It is a proper adaptive icon now,
instead of a square bitmap that each launcher crops to its own shape.

## What changed

**The Android launcher icon** is an adaptive icon: a background, the mark, and a
monochrome layer for Android 13+ themed icons. It used to be a full-bleed square
bitmap, because `mipmap-anydpi-v26/ic_launcher.xml` never existed — so every launcher
fell back to the legacy bitmap and masked that to its own shape. The foreground now
draws the brand mark as the stroke art `logo.svg` defines (it was filling those paths,
which renders a blob, from an older revision of the icon), the legacy bitmaps are
regenerated with a real circle for the round variant, and
`spore-photos-mobile/scripts/generate-icons.sh` regenerates the whole set from
`logo.svg` so the next change is a command rather than an art project.

**Building an APK on a container install:**

- the shipped `compose.yaml` mounts `spore-photos-client/public/apk` into the API, so
  a build is served immediately instead of needing `docker compose up -d --build`;
- the builder image installs Android platform 36, matching `variables.gradle`. It
  shipped 35, so Gradle tried to fetch the right platform at build time and failed with
  `The SDK directory is not writable` — a permissions-shaped message for a version
  mismatch. Build-tools deliberately stays at 35.0.0, which is what the Gradle plugin
  asks for; `scripts/check-release.js` now asserts both values against the files that
  decide them rather than leaving them to drift;
- the documented commands and the ones the panel generates are the complete recipe,
  including the step that publishes the file — and the panel asks for that step only
  when your install actually needs it;
- a build on a fresh checkout works. The client's dependencies are installed when they
  are missing (`vite` is a devDependency, and nothing ever ran `npm ci` for it), and a
  failing build reports itself instead of a bare `sh: 1: vite: not found`.

**The Download App panel:**

- lists APKs on a container install — it read a directory that a built image does not
  have, so it reported "no APK" while the file downloaded fine;
- resolves that directory per request, so what it offers and what downloads cannot
  disagree;
- no longer creates a directory to test whether it can write there (it ran `mkdir -p`
  on a path it requests every time the panel opens);
- answers 404 for an APK that is missing. It used to return the web app's HTML with
  HTTP 200, so a phone downloaded a half-kilobyte "APK" and Android called it a broken
  package;
- hands a container operator a recipe generated for that install shape, rather than a
  command that cannot work where they are.

**Also:** `--init-keystore` explains an unwritable checkout *before* asking for a
passphrase rather than after; the script's hints name a command that exists (`Next:
./scripts/build-apk.sh …` resolved to `/repo/scripts`, a real directory holding no
such script); the Gradle cache is enabled by default as a named volume, so rebuilds
stop re-downloading the Android Gradle Plugin; and `--check --json` reports install
hints only for tools that are actually missing.

## Action required

**Docker.** After `git pull` and the usual `docker compose up -d --build`:

- **Delete `docker/compose.override.yaml` if you added one** to make the APK
  downloadable. `compose.yaml` mounts the APK directory itself now, and a leftover
  override also mounts it at the served path, which shadows whatever the image has
  baked in. It is untracked, so `git pull` will not remove it for you.
- Rebuild the builder image once so it carries platform 36:
  `docker compose --profile build build builder`.

**Manual install.** Nothing beyond the usual upgrade.

**Your phone.** The launcher icon changes only in a new APK, so build one and install
it over the current app — signed with your key it updates in place. Some launchers
cache the old icon until they are restarted.
